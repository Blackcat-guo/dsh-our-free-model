# Our Free Model 2.5.7

## 插件更新

本版本发布 DSH 插件，修复 DSH Tauri 桌面端上 EAC 协付渠道整条不加载的问题（issue #267）。

- **宿主识别改用外壳标记**：DSH Tauri 桌面端用用户实际在用的档案启动内核（本机为 `--profile core-021`），档案名由用户自定，因此原先按 `desktop` / `tauri` profile 名判断的闸门永远认不出真实安装。现在闸门认外壳自己打在进程环境里的 `DSH_TAURI_EMBEDDED=1`（与 `dsh-tauri` 桌面承载适配器同一个变量）。闸门强度未放宽：仅有命令行参数依旧不通过。
- **升级守卫**：闸门是代码，而一键升级会整包替换运行时文件。在暂存校验通过、安装之前，升级流程现在会拒收「随包脚本里没有任何一处认 `DSH_TAURI_EMBEDDED`」的发行版（仅当本进程带桌面标记），已装副本一字未动。判定用文本扫描，不 import 下载内容。
- **发布门覆盖闸门**：`npm run test:release` 的套件集合加入 `vault` 与 `updater`，闸门本体或上面这道守卫退化时发布门直接红。
- **测试不依赖调用者终端**：从 DSH Tauri 会话里跑套件时继承的 `DSH_TAURI_EMBEDDED=1` 会被子进程环境清除，断言「某宿主必须被拒绝」的套件不再测调用者的终端。

独立本地服务和桌面壳不随本版本更新。

## 安装

插件包为 `dsh-our-free-model-2.5.7.tgz`。托管安装请更新 profile 中的可信 tarball 路径，再由宿主重新解析依赖。

## 回退

回退到 `2.5.6` 的插件 tarball，并按宿主的插件安装流程重新解析即可；用户配置、账号和统计数据无需迁移。注意：在 DSH Tauri 桌面端上，2.5.6 及更早版本不认 `DSH_TAURI_EMBEDDED`，回退后 EAC 渠道会再次不可用。
